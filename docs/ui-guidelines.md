# iOSSignKit 界面设计规范

本文以当前生产代码、契约测试和真实运行界面为准。历史设计稿、实施计划、修复轮次和单次截图只用于追溯，不作为独立事实源。

本轮已用 Debug Visual QA 场景核对默认窗口、最小窗口、浅色/深色、历史记录展开、设置页和诊断浮层。截图属于本地验收证据，不进入仓库；界面规则最终应落到代码、测试和本文中。

## 1. 设计目标

iOSSignKit 是常驻菜单栏的 macOS 工具，核心体验不是“频繁操作”，而是让用户快速确认三件事：

1. 目标 iPhone 和目标 App 当前是否可检查、可续签。
2. 个人签名距离到期还有多久，证据是否可信。
3. 此刻最安全的下一步是什么，执行后发生了什么。

界面应保持原生、克制、可信。状态优先于装饰，风险说明优先于促成点击，任何自动化行为都必须可观察、可取消并有结果记录。

## 2. 信息架构与窗口外壳

主面板由固定侧边栏和单一内容区组成，当前只保留三个一级入口：

- `状态`：当前设备、签名有效期、检查链路、主动作与最近结果。
- `历史`：按结果筛选和展开查看续签记录。
- `设置`：目标设备、项目、提醒与自动续期、通用设置。

不再把项目配置、提醒策略拆成独立一级标签。兼容枚举或旧调用可以继续映射到 `设置`，但不得重新出现在导航中。

窗口与侧边栏基线：

| 项目 | 规范 |
| --- | --- |
| 默认窗口 | `912 × 768 pt` |
| 最小窗口 | `860 × 680 pt` |
| 侧边栏 | 固定 `200 pt` |
| 侧边栏导航项 | 高 `32 pt` |
| 主内容 | 页面内部滚动，禁止整窗出现横向滚动 |
| 窗口标题 | `iOS 个人签名续期工具` |

最小窗口下可以让较长按钮文案自然换行，但状态、主动作、设备卡和验证链路必须保持可读，不得依赖隐藏侧边栏才能成立。

## 3. 视觉语言

### 3.1 Renewal Loop

续期环是产品的核心视觉语义，表达“检查—判断—续期—再次检查”的循环。它可以出现在主状态、菜单栏和操作反馈中，但不同尺寸必须复用同一状态模型，不能各自推导业务含义。

- 蓝色表示正常检查、可操作或续期进行中的产品主语义。
- 绿色只用于当前成功反馈。历史成功可以在结果徽章、历史记录中使用成功色，但不得让常驻品牌环持续保持绿色。
- 橙色表示需要注意、临近到期或等待用户处理。
- 红色表示失败、阻断或明确风险。
- 灰色表示离线、未知或尚未建立有效证据。

颜色只能强化含义，任何关键状态都必须同时提供图形或图标和文本说明。

### 3.2 颜色令牌

所有界面颜色从 [`ColorTokens.swift`](../Sources/IOSSignKit/Views/Theme/ColorTokens.swift) 读取，不在组件内重复定义近似色。

| 语义 | 浅色 | 深色 |
| --- | --- | --- |
| 画布 | `#F5F6F8` | `#16181D` |
| 表面 | `#FFFFFF` | `#1F2228` |
| 强调表面 | `#EFF1F5` | `#262A32` |
| 主文本 | `#1D1D1F` | `#F5F5F7` |
| 次文本 | `#6E6E73` | `#98989D` |
| 续期主色 | `#0A84FF` | `#4C9DFF` |
| 成功 | `#34C759` | `#30D158` |
| 警告 | `#FF9500` | `#FF9F0A` |
| 严重 | `#FF3B30` | `#FF453A` |
| 离线 | `#8E8E93` | `#98989D` |
| 日志背景 | `#101216` | `#0B0D10` |

边框使用动态的 `subtle` 或 `strong` 令牌；卡片层级主要依靠表面色、间距和细边框建立，不使用重阴影制造层次。

### 3.3 字体

所有字号和字重从 [`TypeTokens.swift`](../Sources/IOSSignKit/Views/Theme/TypeTokens.swift) 读取：

- 主有效期数字：`56 pt`、圆体、粗体、等宽数字。
- 紧凑有效期数字：`26 pt`、圆体、粗体、等宽数字。
- 页面标题：`20 pt`、semibold。
- 卡片标题与正文：`13 pt`。
- 辅助说明：`12 pt`。
- 眉题：`11 pt`、semibold。
- 日志与技术字段：`11 pt`、等宽。

日期、倒计时和有效期数字必须使用等宽数字，避免刷新时发生水平跳动。

### 3.4 间距、圆角与控件高度

统一使用 `4 / 8 / 12 / 16 / 20 / 24 / 32 pt` 间距序列。卡片圆角 `12 pt`，普通控件圆角 `8 pt`，胶囊状态使用完全圆角。

| 控件 | 高度 |
| --- | --- |
| Hero 主动作 | `44 pt` |
| 普通主控件 | `36 pt` |
| 次级控件 | `28 pt` |
| 侧边栏导航项 | `32 pt` |

页面通常使用 `20 pt` 外边距和 `12 pt` 区块间距。新增组件应优先组合现有令牌，不引入只服务单个页面的零散尺寸。

## 4. 状态页

状态页是主旅程，不是数据仪表盘。它按下列顺序组织：

1. Hero 状态区：续期环、有效期或状态主文案、解释文本和安全主动作。
2. 目标设备卡：设备名、连接方式和可用性摘要。
3. 验证链路：环境、设备、目标 App 三步检查结果。
4. 最近结果或操作反馈：展示本次动作结算，不把历史动作误当成当前动作。

当前 Hero 基线：续期环直径 `132 pt`、线宽 `10 pt`；Hero 内容最小高度 `176 pt`；目标设备卡 `230 × 98 pt`。这些尺寸由 [`StatusDashboardComponents.swift`](../Sources/IOSSignKit/Views/Components/StatusDashboardComponents.swift) 维护。

### 4.1 状态文案

- 主标题只回答“现在是什么状态”，例如等待连接、可续签、正在检查、续签成功。
- 次文案解释证据和影响，不重复主标题。
- 恢复建议使用动词开头，并明确对象，例如“解锁 iPhone 后重新检查”。
- 未知与失败必须区分：无法确认不是已失败，离线也不是目标 App 未安装。
- 预计时间必须保留“预计”语义，不把推断值写成证书权威事实。

### 4.2 动作层级

- 同一状态区最多一个视觉主动作。
- `重新检查`只重新获取环境、设备和安装证据，不暗示会部署。
- `重新签名并安装`属于高影响动作；策略不明确时使用省略号并先呈现选择或确认。
- 默认按钮和 Return 键不得直接触发部署。
- 自动续期倒计时、等待恢复和部署必须提供符合当前阶段的取消动作。
- 只有当前部署明确关联的失败反馈才可以提供`重试`；历史失败和通用提示不得继承该动作。

### 4.3 活动反馈区

状态页主旅程使用统一活动反馈卡，覆盖检查、倒计时、部署、自动恢复、结算结果和一般反馈。

- 当前操作和历史结果分开判断。
- 部署进行期间，任务卡下方常驻独立的`实时输出`面板，复用当前部署日志并自动跟随最新内容；面板必须保持有界高度、支持滚动和文本选择，不得让长日志无限扩张主旅程。
- 任务卡只保留当前阶段的关键操作；完整日志入口放在实时输出面板标题栏中，并通过`展开`打开主面板浮层。非部署阶段不得展示实时输出面板。
- 关闭反馈只影响展示，不清除持久化历史，也不能解除进程恢复阻断。
- 细进度线只表示活动，不伪造无法计算的百分比。

## 5. 历史页

历史页按日期分组，顶部使用`全部 / 成功 / 失败 / 已取消`筛选胶囊。每条记录默认只显示时间、结果、目标摘要和简短结论；展开后再显示日志摘要和`打开完整日志`动作。

- 成功、失败、取消同时使用图标、文本和语义色。
- 筛选只改变可见记录，不改变状态页的当前安装证据。
- 日志使用深色固定背景和等宽字体，保留可复制性。
- 分页加载更多记录，避免一次解析整个日志目录。
- 空状态要说明是“没有记录”还是“当前筛选没有结果”。

## 6. 设置页

设置页使用固定在标题下方的四分类选择器：

1. `目标`：目标设备和项目。
2. `续期`：提醒/自动续期策略和检查频率。
3. `局域网`：服务、连接和安全。
4. `通用`：登录启动和诊断。

分类选择器宽 `480 pt`、高 `52 pt`，支持点击和左右方向键循环切换，并用文本、选中背景、焦点描边和错误标记共同表达状态。每个分类维护独立的垂直滚动内容，不出现横向滚动。

底部保存栏固定可见，包含`恢复默认设置…`和`存储更改`，负责提交`目标`、`续期`和`局域网`草稿。存在未保存更改时允许点击存储；如果草稿校验失败，界面切换到对应分类并展示错误，而不是让按钮提前失效后无法定位问题。恢复默认必须先确认，只修改`续期`和`局域网`草稿，不改变目标或通用设置，也不绕过最终的显式存储。

### 6.1 目标设备

- 设备选择控件高 `56 pt`，同时展示名称和稳定 ID 的安全摘要。
- 已固定设备离线时仍显示已保存名称，不用当前扫描列表覆盖配置事实。
- 自定义或扫描结果弹层宽度限制在 `360–520 pt`，长名称截断时保留完整辅助说明。
- 匹配歧义、ID 缺失和来源冲突必须阻止保存为可部署目标。

### 6.2 项目

- 项目目录、Project/Workspace、Scheme、iOS App Target 和 Bundle ID 共同组成已解析目标。
- 自动推断结果必须可检查；解析失败时指出缺少哪个条件。
- 只解析出一个 App 候选时自动选择；解析出多个候选时显示明确的目标选择控件，不得只显示“请选择”诊断而没有可执行入口。
- 多候选选项以 `Scheme · Target` 为主信息，以 Bundle ID 和工程名为辅助信息；已有配置与候选唯一精确匹配时恢复该选择，否则保持未选择并禁止保存。
- 切换候选必须同步更新工程路径、Scheme、Target 和 Bundle ID，不能组合来自不同候选的字段。
- 路径展示可以省略中间段，但辅助功能和复制内容应保留完整值。
- 界面不得把缓存、历史记录或其他候选中的 Scheme、Target、Bundle ID 当作配置回退。
- 只解析到 Framework、Library 或其他不生成独立 `.app` 的 Target 时，应明确说明其不能安装到真机，不得只显示笼统的“项目无效”。

### 6.3 续期

- 策略只展示`到期时提醒`和`到期时自动刷新`。
- 到期前检查间隔允许 `1–60` 分钟，默认 `5` 分钟。
- 确认到期后的检查间隔允许 `1–60` 分钟，默认 `1` 分钟。
- 提醒冷却允许 `1–72` 小时，默认 `24` 小时。
- 数字步进器高 `36 pt`，中间数值区 `60 pt`，加减按钮 `28 pt`。
- 自动模式旁必须解释设备解锁、Xcode 准备和部署前复核等约束。

### 6.4 局域网

- 局域网控制按`服务 / 连接 / 安全`三个卡片组织，默认关闭；服务运行、启动失败和草稿校验状态必须可见。
- 连接卡展示主机、端口、完整链接、复制动作和一次性二维码入口。未存储的草稿不得生成可分享链接；二维码浮层必须提供明确关闭动作并支持 Escape。
- 安全卡提供密码、确认密码和显示密码选项。密码至少 6 个字符，启用服务时必须已有凭据或输入一致的新密码；界面不得回显已保存密码。
- 局域网控制页脚注必须表明只限同一局域网访问。远程续签需要现场选择 Profile 策略时，应明确要求回到 Mac 操作，不能把拒绝伪装成已开始。

### 6.5 通用

登录时启动属于应用级设置，开关直接同步系统服务，不等待底部保存栏。系统服务状态、保存值和当前实际状态不一致时，应展示可恢复诊断，不能只更新开关外观。

## 7. 菜单栏与右键菜单

菜单栏是快速状态入口，主面板是完整工作台：

- 左键打开并前置主面板；已最小化时恢复。
- 右键打开原生菜单。
- 菜单栏标题根据可用宽度分级收敛，不能无限占用状态栏。
- 主面板关闭后应用恢复为 accessory 行为，不制造多实例。

右键菜单顶部使用 `300 × 54 pt` 的双行动态摘要，命令顺序固定为：

1. 打开面板
2. 重新检查
3. 重新签名并安装（需要策略选择时显示省略号）
4. 打开项目
5. 退出 iOSSignKit

菜单必须使用原生 `NSMenu` 交互和键盘行为。顶部摘要可以自定义绘制，但不得让整张菜单退化为自绘浮层。

## 8. 动效与可访问性

动效只表达状态变化，不用于装饰性循环吸引注意。统一使用 [`MotionTokens.swift`](../Sources/IOSSignKit/Views/Theme/MotionTokens.swift)：快速 `0.15 s`、常规 `0.24 s`、慢速 `0.40 s`、分段延迟 `0.06 s`。

- 遵循系统 Reduce Motion；启用后关闭无限循环，保留必要的即时状态切换。
- 主面板不可见时暂停续期环动画；恢复可见后从当前状态继续，不追赶后台经过时间。
- 状态切换不能造成页面结构大幅跳动。
- 所有图标按钮提供可读标签；颜色不是唯一信息通道。
- 键盘焦点、默认按钮和取消按钮必须与风险等级一致。
- 浅色与深色应保持相同的信息层级和几何布局，不为某一外观单独改动业务结构。

## 9. 内容与术语

- 产品展示名统一为 `iOSSignKit`，副标题统一为`iOS 个人签名续期工具`。
- 对用户使用`重新签名并安装`或`续签`，不要用内部的 deploy、profile、rollout 代替主文案。
- 技术诊断可以显示 Xcode、CoreDevice、Bundle ID、Scheme 等准确术语。
- 文案不承诺必然获得新的 7 天有效期；`force`与`auto`策略必须解释实际差异。
- 不使用开发阶段或方案代际名称描述当前页面、组件或交互。

## 10. 变更与验收

界面结构、导航、状态语义、视觉令牌或关键交互发生变化前，先与维护者确认是否以及如何更新本文。需要在 `docs/` 新增、拆分或重命名文档时也必须先确认。

视觉改动的最小检查集：

1. 默认窗口与 `860 × 680 pt` 最小窗口。
2. 浅色与深色外观。
3. 状态、历史、设置三个一级入口。
4. 历史展开、日志浮层或诊断浮层等覆盖层。
5. 离线、未知、警告、成功、失败和进行中状态。
6. Reduce Motion 和键盘主路径。

普通功能或界面修改是否需要运行截图验收，仍遵循项目根目录 [`AGENTS.md`](../AGENTS.md) 的验证约定。
